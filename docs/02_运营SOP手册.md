# 02 运营SOP手册

> 版本：v1.0 | 生效日期：2026年6月 | 负责部门：运营管理部
> 本手册涵盖企业评价平台日常运营的8项标准操作流程，所有运营人员须严格遵照执行。

## 一、内容审核流程

### 1.1 流程概述

| 项目 | 说明 |
|------|------|
| **流程编号** | SOP-OP-001 |
| **流程名称** | 内容审核流程 |
| **适用场景** | 用户提交评价、评论、回复、图片等所有用户生成内容（UGC） |
| **核心原则** | 先审后发，分级审核，全程留痕 |
| **审核时效** | 机器初审即时完成（<100ms），人工复审不超过30分钟（工作时间） |

### 1.2 流程图

```
用户提交内容
     │
     ▼
┌─────────────┐
│ 1. 机器初审   │ ← 敏感词库匹配 + AI语义分析
└──────┬──────┘
       │
  ┌────┴────┐
  │ 判定结果  │
  └────┬────┘
       │
   ┌───┼───┐
   ▼   ▼   ▼
 PASS   BLOCK   REVIEW
   │     │       │
   ▼     ▼       ▼
 直接   驳回    ┌──────────┐
 发布   (告知   │ 2. 人工复审 │ ← 审核员操作
       原因)   └─────┬────┘
                     │
              ┌──────┼──────┐
              ▼      ▼      ▼
           通过    驳回    要求修改
              │      │       │

           直接    告知     退回用户
           发布    原因+    修改后重提
                  申诉      (3次机会)
                  渠道
```

### 1.3 审核标准

| 审核等级 | 判定标准 | 处置方式 | 示例 |
|---------|---------|---------|------|
| PASS（直接通过） | 无敏感词、AI评分<0.3、无违规特征 | 即时发布 | 客观公正的评价，无违规内容 |
| BLOCK（直接拦截） | 命中高危敏感词、AI评分>0.8 | 驳回，告知原因 | 包含侮辱性词汇、政治敏感内容 |
| REVIEW（人工复审） | AI评分0.3-0.8之间，或命中中危敏感词 | 转入人工审核队列 | 内容模糊，需人工判断意图 |

### 1.4 人工审核操作规范

| 步骤 | 操作内容 | 操作人 | 时限 | 记录要求 |
|------|---------|--------|------|---------|
| 1. 领取任务 | 审核员从审核队列中领取待审内容 | 审核员 | - | 系统自动记录领取时间 |
| 2. 内容审查 | 阅读评价全文，对照审核标准逐项检查 | 审核员 | <10分钟/条 | 标注审核依据 |
| 3. 证据核实 | 如涉及具体事实陈述，核对用户上传的凭证材料 | 审核员 | <5分钟 | 记录凭证核实结果 |
| 4. 做出判定 | 选择"通过"、"驳回"或"要求修改" | 审核员 | <2分钟 | 选择判定理由分类 |
| 5. 填写理由 | 驳回/要求修改时，必须填写具体理由 | 审核员 | <3分钟 | 理由模板选择+补充说明 |
| 6. 提交审核 | 点击提交，系统自动通知用户 | 审核员 | <1分钟 | 系统记录审核人、时间、结果 |

### 1.5 审核质量抽检

| 抽检项目 | 频率 | 抽样比例 | 负责人 | 不合格处置 |
|---------|------|---------|--------|-----------|
| 审核准确性抽查 | 每日 | 5% | 审核组长 | 驳回重审，记录错误类型 |
| 审核时效性检查 | 每日 | 全部 | 系统自动 | 超时告警，纳入KPI考核 |
| 审核一致性检查 | 每周 | 同内容双盲审核对比 | 审核组长 | 偏差>20%时重新培训 |
| 用户申诉复核 | 按申诉量 | 100% | 高级审核员 | 申诉成立则撤销原判定 |

## 二、投诉工单处置流程

### 2.1 流程概述

| 项目 | 说明 |
|------|------|
| **流程编号** | SOP-OP-002 |
| **流程名称** | 投诉工单处置流程 |

### 2.3 各环节操作规范

| 环节 | 操作内容 | 责任人 | 时限 | 输出物 |
|------|---------|--------|------|--------|
| 1. 受理登记 | 生成工单，记录投诉人信息、被投诉内容URL、投诉类型 | 客服专员 | 即时 | 投诉工单 |
| 2. 形式审查 | 检查投诉人身份证明、权属证明、侵权内容说明、初步证据 | 客服专员 | 2小时内 | 形式审查意见 |
| 3. 通知补正 | 材料不齐全的，一次性告知需补正的材料清单 | 客服专员 | 形式审查后即时 | 补正通知书 |
| 4. 内容核查 | 核实被投诉内容是否违规，对照平台规则和法律法规 | 内容审核员 | 4小时内 | 核查报告 |
| 5. 处置执行 | 违规内容下架/屏蔽/删除，记录处置措施 | 内容审核员 | 核查后即时 | 处置记录 |
| 6. 结果反馈 | 向投诉人发送处置结果通知，含处理结果和理由 | 客服专员 | 处置后即时 | 结果通知书 |
| 7. 结案归档 | 工单关闭，所有材料电子化归档，补正期限届满后归档 | 客服专员 | 结案后即时 | 归档记录 |

### 2.4 投诉类型与处置标准

| 投诉类型 | 证明材料要求 | 核查要点 | 处置措施 |
|---------|-------------|---------|---------|
| 名誉权/商誉侵权 | 营业执照+授权书+具体侵权说明 | 是否构成侮辱诽谤/是否虚假事实 | 成立则屏蔽/删除 |
| 个人信息泄露 | 身份证+被泄露信息截图 | 是否包含身份证号/手机号/住址等 | 成立则脱敏处理 |
| 知识产权侵权 | 权利证明+侵权比对说明 | 是否构成侵权 | 成立则删除侵权内容 |
| 虚假评价 | 在职/消费凭证+事实反驳 | 评价内容是否属实 | 成立则标注争议/删除 |
| 恶意刷评 | 批量链接+刷评特征说明 | IP/时间/内容模式分析 | 成立则批量删除+封号 |

| 触发类型 | 触发条件 | 响应时限 | 责任人 |
|---------|---------|---------|--------|

| 监管通知 | 收到网信办/公安等监管部门通知 | 4小时内完成 | 法务合规部+内容安全团队 |
| 热点事件 | 涉及平台的重大舆情/社会热点事件 | 8小时内完成 | 内容安全团队 |
| 用户反馈 | 用户通过投诉渠道反馈漏拦/误拦 | 24小时内评估 | 内容安全团队 |
| 内部巡检 | 审核团队发现漏拦/误拦模式 | 发现后48小时内处理 | 内容安全团队 |

### 3.4 词库变更审批权限

| 变更类型 | 审批层级 | 审批人 |
|---------|---------|--------|

| 新增单个词条（高危） | 二级审批 | 内容安全负责人+法务合规部负责人 |
| 批量新增词条（>10条） | 二级审批 | 内容安全负责人+法务合规部负责人 |
| 批量新增词条（>100条） | 三级审批 | 内容安全负责人+法务合规部负责人+CTO |
| 删除词条 | 二级审批 | 内容安全负责人+法务合规部负责人 |
| 修改处置等级 | 二级审批 | 内容安全负责人+法务合规部负责人 |

## 四、风控告警处置流程

### 4.1 流程概述

| 项目 | 说明 |
|------|------|
| **流程编号** | SOP-OP-004 |
| **流程名称** | 风控告警处置流程 |
| **适用场景** | 风控系统自动检测到异常行为（批量注册、刷评、恶意攻击、数据异常等）触发的告警 |
| **核心原则** | 告警必核实，处置有依据，高危即时响应，全程可追溯 |

### 4.2 告警等级与响应时限

| 告警等级 | 定义 | 示例 | 响应时限 | 通知方式 |
|---------|------|------|---------|---------|
| P0-紧急 | 严重影响平台安全或合规 | 大规模数据泄露、系统性攻击、涉恐涉暴内容 | 15分钟内 | 电话+短信+IM |
| P1-高危 | 可能导致法律风险或重大用户影响 | 批量刷评、有偿删帖嫌疑、重大舆情事件 | 30分钟内 | 短信+IM |
| P2-中危 | 需关注但影响可控 | 异常发帖频率、疑似刷分行为 | 2小时内 | IM通知 |
| P3-低危 | 需记录但无需立即处置 | 单个可疑账号、轻微违规 | 24小时内 | 系统通知 |


### 5.3 审批层级

| 调证类型 | 审批层级 | 审批人 |
|---------|---------|--------|
| 一般调证（单个用户基本信息） | 一级审批 | 法务合规部负责人 |
| 一般调证（用户评价内容） | 二级审批 | 法务合规部负责人+CTO |
| 批量调证（>10个用户） | 三级审批 | 法务合规部负责人+CTO+CEO |
| 涉及敏感个人信息批量调证 | 三级审批 | 法务合规部负责人+CTO+CEO+DPO |
| 紧急调证（涉及公共安全） | 先配合后补批 | 事后24小时内补全审批 |

### 5.4 数据提供原则

| 原则 | 说明 |
|------|------|
| 合法性原则 | 仅对合法有效的法律文书进行配合 |
| 最小化原则 | 严格按调证范围提供数据，不得超范围提供 |
| 保密性原则 | 不得向被调证用户或其他第三方透露调证情况 |
| 留痕原则 | 所有调证流程全程留痕，保存不少于3年 |

## 七、应急响应流程

### 7.1 流程概述

| 项目 | 说明 |
|------|------|
| **流程编号** | SOP-OP-007 |
| **流程名称** | 应急响应流程 |
| **适用场景** | 平台出现重大违规内容、数据安全事件、系统安全事故等紧急情况 |
| **核心原则** | 发现即上报，先止损后追责，快速响应，持续改进 |

### 7.2 应急响应等级

| 等级 | 定义 | 示例 | 响应时限 | 上报层级 |
|------|------|------|---------|---------|
| I级-特别重大 | 影响平台存续或涉及国家安全 | 平台被用于传播危害国家安全信息、大规模数据泄露(>10万条) | 15分钟内 | 总经理+董事会+监管部门 |
| II级-重大 | 严重影响平台运营或涉及刑事风险 | 涉恐涉暴内容大面积传播、数据泄露(1万-10万条) | 30分钟内 | 总经理+法务负责人 |
| III级-较大 | 影响部分功能或涉及行政处罚风险 | 局部违规内容传播、数据泄露(<1万条) | 1小时内 | 部门负责人+法务负责人 |
| IV级-一般 | 轻微影响，可控范围 | 个别违规内容、系统短暂故障 | 2小时内 | 值班负责人 |
